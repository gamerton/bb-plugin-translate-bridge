# Translate Bridge — плагин bb

[English documentation](README.md)

## Установка из GitHub

Нужен BB 0.48+ и Plugin SDK 0.6.94+.

```sh
bb plugin install git:https://github.com/gamerton/bb-plugin-translate-bridge.git@v0.2.0
```

BB сам установит зависимости и соберёт плагин. Отдельно скачивать архив или
распаковывать исходники не требуется.

Вы пишете и читаете по-русски, а дорогая основная модель получает, обдумывает и пишет ответы
только на английском. Перевод в обе стороны делает отдельная дешёвая модель: локальная
(llama.cpp, Ollama, LM Studio) или внешняя (OpenRouter, OpenAI, любая модель из каталога bb).

## Как пользоваться

1. В композере треда нажмите кнопку с иконкой перевода. Когда перевод включён, на кнопке
   написано **RU→EN**. В композере нового треда та же кнопка включает перевод для тредов,
   которые вы создадите дальше.
2. Стрелка рядом с кнопкой открывает выбор переводчика:
   - **Локальный / API** — OpenAI-совместимый сервер. Адрес по умолчанию —
     `http://127.0.0.1:8080/v1` (llama.cpp); модель берётся из списка `/models` или вводится вручную;
   - **Модель bb** — тот же выбор провайдера и модели, что и для основной модели. Каждый перевод
     для Claude Code, Codex и OpenCode 2.x выполняется отдельным вызовом CLI
     с короткой инструкцией перевода и без инструментов. Остальные провайдеры используют скрытый тред.

   Переводчик можно задать для одного треда или по умолчанию и сменить в любой момент диалога.
   В диалоге есть кнопка «Перевести», чтобы проверить выбранную модель.
3. В чате вместо оригиналов показаны переводы. Под каждым сообщением есть ссылка
   **Показать оригинал** (у ответа модели) или **Показать, что ушло модели** (у вашего
   сообщения). То же переключение есть в меню действий сообщения. Команда палитры
   «Translate Bridge: показывать оригиналы…» и флажок в диалоге переключают все сообщения сразу.

Горячая клавиша **Ctrl+Alt+T** включает и выключает перевод в текущем треде.

## Как это устроено

- **Ваше сообщение → модель.** Хук `message.dispatch` придерживает сообщение: на карточке очереди
  видно «Перевожу на английский…». Затем строка очереди заменяется переводом, и сообщение уходит.
  Слэш-команда в начале сообщения, блоки кода и упоминания файлов из композера защищены
  от изменения. Инлайн-код, пути и команды могут входить в текст запроса; переводчику
  дано указание сохранить их без изменений. Если перевод не удался, на карточке видна причина.
  Можно сменить переводчик (тогда перевод повторится) или нажать «Отправить сейчас», чтобы
  отправить оригинал.
- **Модель → вы.** Каждый законченный ответ переводится обратно, перевод сохраняется в базе плагина.
- **Инструкция модели.** В тредах с переводом модель получает короткую инструкцию: думать и
  отвечать по-английски и не упоминать перевод. После включения перевода к первому сообщению
  добавляется такое же скрытое от вас напоминание (блок `agent-only`), потому что инструкции
  применяются только с новой сессии провайдера.
- **Проверка результата.** Если переводчик вернул исходный текст или текст не на том языке,
  запрос повторяется с напоминанием. Если и повтор не помог, сообщение модели не отправляется.

## Настройки

Настройки → Installed plugins → Translate Bridge, или
`bb plugin config translate-bridge set <ключ> <значение>`:

| ключ | по умолчанию | смысл |
| --- | --- | --- |
| `userLanguage` | Russian | ваш язык |
| `modelLanguage` | English | язык основной модели |
| `openAiBaseUrl` | `http://127.0.0.1:8080/v1` | OpenAI-совместимый сервер |
| `openAiApiKey` | — | ключ сервера (секрет) |
| `newThreadsDefault` | false | включать перевод в новых тредах |
| `timeoutSeconds` | 240 | таймаут одного перевода |

Для локального сервера плагин отправляет `chat_template_kwargs.enable_thinking=false`, чтобы
модели семейства Qwen3 не тратили время на рассуждения.

## Claude Code без агентского контекста

При выборе провайдера `claude-code` плагин запускает `claude -p` на машине
окружения исходного треда, из каталога этого окружения. В системный промпт
передаётся только инструкция перевода; текст поступает через stdin.
Встроенные инструменты отключены (`--tools ""`), MCP отключён пустой строгой
конфигурацией, навыки и команды отключены. Сессия не сохраняется.
`--bare` не используется: обычная авторизация CLI сохраняется.

CLI использует собственные настройки и унаследованную среду host worker;
это не полноценная сессия провайдера BB. Переменные, которые BB добавляет только
при запуске агентского треда, автоматически не переносятся. Для таких подключений
настройте авторизацию/адрес в собственных настройках Claude CLI на выбранной машине.
`BB_CLAUDE_CODE_EXECUTABLE`, если доступен в среде host worker, задаёт путь к CLI;
иначе используется `claude` из PATH. При ошибке плагин не откатывается к треду
с полным контекстом. Таймаут, отмена и перезагрузка останавливают процесс перевода.
Выбранный поддерживаемый `effort` сохраняется; отключение инструментов не означает
отключения внутренних рассуждений модели.

## Codex и OpenCode без агентского контекста

- **Codex** (`codex`): `codex exec --ephemeral --ignore-user-config --ignore-rules`.
  Штатная авторизация сохраняется, пользовательский `config.toml` не загружается.
  Системная инструкция заменяется инструкцией переводчика; инструменты, MCP,
  плагины, навыки и инструкции проекта исключены. Запуск идёт из временного
  каталога, файлы инструкции и результата удаляются после вызова. Собственные
  API-провайдеры и прочие настройки из пользовательского `config.toml` в этом
  режиме не применяются. Выбранный reasoning передаётся как `model_reasoning_effort`.
- **OpenCode 2.x** (`acp-opencode`): отдельный `opencode run --standalone` с агентом
  `translate-bridge`. Его `system` заменяет базовый prompt, а wildcard deny
  убирает инструменты из запроса. Используются обычные конфигурация провайдеров
  и база авторизации OpenCode. Для каждого перевода создаётся новый session ID;
  после вызова плагин удаляет только эту сессию через `opencode session delete`.
  После аварии процесса сессия может остаться в истории. Временный проектный
  конфиг удаляется. Выбранный reasoning передаётся как вариант `provider/model#variant`.
  Реализация проверена на OpenCode 2.0.27; V1 не поддерживается этим путём.

В обоих CLI остаётся небольшое служебное описание окружения. Плагин не возвращается
к обычному агентскому треду при ошибке. Авторизация берётся из CLI на машине
исходного треда; настройки и переменные, которые BB добавляет только провайдеру
агентского треда, автоматически не переносятся.

## CLI

```
bb translate-bridge status [thread-id]
bb translate-bridge on|off <thread-id>
bb translate-bridge test <текст>
```

## Ограничения

- В bb нет слота, который заменяет тело сообщения. Поэтому переводы встраиваются в ленту по
  атрибутам `data-timeline-row-id` и `data-message-column`. Если интерфейс bb изменится и эти
  атрибуты пропадут, чат просто покажет оригиналы на английском, ничего не сломается.
- Ответ переводится, когда он закончен, а не по мере стриминга. Пока ответ пишется, он виден на
  английском.
- Рассуждения модели («Thought»), вызовы инструментов и планы не переводятся.
- «Отправить сейчас» на карточке очереди по замыслу bb обходит хук: сообщение уйдёт без перевода.
